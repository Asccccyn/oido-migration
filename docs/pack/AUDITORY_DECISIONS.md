| ID | 最终决定 |
|---|---|
| D01 | 独立项目/服务。正式名 **oído**；代码、仓库、包名使用 `oido`；Claude 工具组显示名 **“我只听你”**。内部模块化单体 + 隔离 worker，不把 Siren 或 estómago 改造成新耳朵本体。 |
| D02 | 宿主用户原声与周char实际 TTS 原声一等支持。TTS 必须区分 `generated / emitted / playback_reported`；每条绑定 `voice_profile_id + voice_profile_version + provider/model + actual audio asset`，旧音色与新音色不混基线。 |
| D03 | 周char默认读取**文字韵律谱**；图片、频谱、波形、F0图按需展开。先做 Web/iOS/Claude Code/estómago 四入口随机码图片测试，模型实际读到才算支持。 |
| D04 | C01–C16 全部保留。普通话加入汉字/拼音/声调、字内 F0、句级趋势和相对半音。F0 必须使用真实采样率并覆盖 16/24/44.1/48 kHz。**情绪分类标签不生成、不持久化、不注入。** 笑、叹气、抽泣样、呼吸、Meow、Purr 等作为带时间的声音事件。 |
| D05 | 宿主用户私密原声只在 Mac mini 本地做 oído 分析。不得新增第三方云端音频推理 provider，不得本地失败后 remote fallback。发送到 Claude 的仅是当前会话按需使用的派生文字/图片/证据。 |
| D06 | 正式录音默认持续保留，宿主用户可随时删除。允许建立“平时的宿主用户”个人声学基线：仅音高、语速、停顿等经质量门槛筛选的统计；**不含绝对音量，不做人声身份识别，可随时清空，清空后不得从旧历史静默重建。** |
| D07 | Chat 与 estómago 权限等价但传输方式不同。Chat 的“听听我刚发的”走 Siren `voice_list`/实际等价能力**拉取**最近获授权资产，再交给 oído；不得假定服务端可主动 push。四入口分别验收。 |
| D08 | Mariposa 只保存获授权 `audio_id + range + revision` 关联并遵循当前检索、原文、“我们的话”、I 版本及其他现行记忆规则。声音转写不冒充原文，embedding 不进入普通召回。 |
| D09 | 验收必须包含：采样率/F0正确性、普通话声调与句调分离、事件误报、个人基线 clear、周char音色版本比较、四入口图片运输、文字韵律谱 vs 加图盲测、资源和故障隔离。 |
| D10 | GLM 按 OIDO-EXEC-1.1 实施。先 P0：采样率正确性、四入口图片运输、Siren URL SSRF、安全/权限；再接离线全量、Siren/estómago、实时、Mariposa。所有生产接入必须 feature flag 可退，不能覆盖其他项目未提交改动。 |

## 不可被实现便利改写的边界

- oído 不常驻偷听，只处理明确交付的录音、获授权通话和实际 TTS 产物。
- 默认感知输出不出现 `sad/happy/angry/neutral/anxious` 等心理状态标签。
- 普通话词汇声调与句级语调必须分开描述；无法可靠分离时输出 uncertain。
- 宿主用户基线不是声纹，不做“是不是宿主用户”的识别。
- 正式原声不会因分析完成自动删除；owner 删除权高于 pin、缓存和长期关联。
